# ADR-0005: Packaging, licensing and update strategy

- Status: Accepted
- Date: 2026-11-06
- Inputs: [packaging-and-licensing.md](../research/packaging-and-licensing.md) (R5)

## Context
- Granary is AGPL-3.0-or-later, Windows 11 x64 only, hosted in a **private** GitHub repo.
- libmpv source per prompt CONFIG: shinchiro/mpv-winbuild-cmake `mpv-dev-x86_64-v3-*.7z`. These builds are GPLv3
  (`--enable-gpl --enable-version3`), x86-64-v3 (AVX2), contain `libmpv-2.dll` + headers + `libmpv.dll.a` but **no
  MSVC `.lib`/`.def`**. shinchiro keeps only ~30 daily releases, so pinned URLs expire after about a month.
- Tauri CLI 2.12.4 / bundler 2.10.4: NSIS supports `installMode: "currentUser"`; WebView2 modes include
  `downloadBootstrapper` (default) and `embedBootstrapper`. WebView2 is preinstalled on Windows 11.
- The Tauri updater needs a publicly reachable endpoint; private-repo release assets require a token.
- Private-repo CI is billed from a monthly dollar budget (~1,200 Windows minutes on Free).

## Options
- libmpv: (1) shinchiro v3 (CONFIG); (2) shinchiro baseline x86_64; (3) official mpv v0.42.0 LGPL zip (new since
  2026-11-05, not covered by the owner's download approval).
- Linking: generated import lib (`lib /def`) vs runtime `LoadLibrary`.
- Installer: NSIS per-user vs MSI.
- Updates: Tauri updater vs manual check vs none.

## Decision
- **libmpv**: shinchiro `mpv-dev-x86_64-v3-20261106-git-9028187538.7z`, SHA-256
  `a778b3444b0b8b6d93cb00ca49f2acf62a02d0b61249229fc9944672f80683bb`, pinned in `scripts/libmpv.pin.json` and
  fetched/verified by `scripts/fetch-libmpv.ps1`. Primary-target desktops (OLED HDR gaming PCs) all have AVX2; the
  baseline x86_64 build is a drop-in alternative if a non-AVX2 report appears (one-line pin change).
- **Link-time** via an MSVC import library generated by `fetch-libmpv.ps1` from the DLL's exports (`dumpbin` →
  `.def` → `lib /def`). Delay-load is unnecessary; the DLL ships next to the exe.
- **Pin expiry**: CI caches `vendor-bin/download/<asset>` with key = sha256 (`actions/cache`), so builds keep working
  after shinchiro deletes the release; when the cache is gone, bump the pin (fetch-libmpv skill documents how).
  The verified archive is also attached to each draft release as the Corresponding Source companion record.
- **Installer**: Tauri NSIS only, `installMode: "currentUser"` (no admin, `%LOCALAPPDATA%\Granary`), WebView2
  `downloadBootstrapper` (no-op on Windows 11), `libmpv-2.dll`, default `mpv.conf`, `LICENSE`,
  `THIRD_PARTY_NOTICES.md` bundled via `bundle.resources` so the DLL lands next to `granary.exe`. Original icon.
- **Licensing obligations**: AGPL + GPLv3 combine (§13 of each). Each binary release links to the exact Granary
  source commit and lists mpv commit `9028187538`, the FFmpeg commit (read from `ffmpeg-version` at runtime, recorded
  in THIRD_PARTY_NOTICES) and the shinchiro build recipe commit. About screen shows the AGPL source link and FFmpeg
  credit.
- **Updates**: no auto-updater. The About screen has "Check for updates", which opens the repository's releases page
  in the browser (the owner is signed in to GitHub; no token ships in the app). A public update feed is a future
  decision (it would require public source under AGPL anyway).
- **CI budget**: `ci.yml` (push) runs checks only, with rust-cache and pnpm cache; `release.yml` (tag `v*`) builds
  the installer and creates a **draft** release.
- **Signing**: not configured; options documented in `docs/signing.md`.

## Consequences
- The installer is unsigned: SmartScreen/Smart App Control warnings are expected (documented).
- Users on pre-Haswell / Atom-class CPUs cannot run the v3 build (documented in README requirements).
- THIRD_PARTY_NOTICES must be updated on every pin bump.
