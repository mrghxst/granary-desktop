## Findings

### High
None.

### Medium

- **M1 After the network returns, failed screens never reload, although the banner says Granary will reconnect.**
  `components/OfflineBanner.tsx:4,9-11`, `i18n/en.json` `status.offline`, `routes/ServerHome.tsx:55,63-77`,
  `lib/events.ts:33-43`, `components/Shell.tsx:73-90`.
  - **Mechanism:**
    - The banner's `online` handler only hides the banner (`setOnline(true)`). Nothing else listens for `online`. The
      only reload triggers are `bumpRefresh()` from a server event (`Shell.tsx:81`) and the end of playback
      (`PlayerProvider.tsx:96,100`); the events socket reconnecting does not emit anything (`events.rs:40`).
    - Error alerts have no Retry control, and clicking the sidebar link of the current route does not remount it.
    - `ServerHome` sets `error` on failure but never clears it (`setError` is only called at L73). After any later
      successful load (refresh tick), the stale error alert stays above the fresh rows.
    - The banner text promises "Granary will reconnect when the network is back"; the component comment says "pages …
      retry on their own". Neither is true for page data. The checklist step even expects a reload only "on the next
      navigation" (`MANUAL_TEST_CHECKLIST.md:151-152`).
  - **Failure scenario:** the laptop wakes from sleep and Wi-Fi needs a few seconds. The user opens a server: ServerHome
    shows "Server unreachable" and the amber banner. Wi-Fi connects and the banner disappears, but the page still shows
    only the error, with no rows and no Retry button. Clicking "Home" in the sidebar does nothing (same route). The user
    has to go to another screen and back. The same applies to Library and Item (`useLoad` keeps the error until the key
    or the refresh tick changes). If a server event later bumps the refresh, ServerHome shows the rows *and* the old
    error.
  - **Fix:** call `bumpRefresh(0)` from the `online` handler (and optionally when the events socket reconnects). In
    ServerHome, clear `error` on success (or move it to `useLoad`). Add a "Retry" button to network-class errors
    (`unreachable`, `timeout`, `unavailable`) that bumps the refresh. Add a vitest case: error → `online` event →
    reload → error gone. Align the banner text and checklist step with the behaviour.

- **M2 Items deferred to "Phase 8 polish" in PROGRESS.md are neither done nor re-targeted.** `PROGRESS.md` "Known
  issues" (the lines "Phase 5 review lows deferred …", "Phase 6 review lows deferred …", "Next episode does not cross
  a season boundary … Phase 8 polish"); `lib/player.ts:283-320`; `components/ContextMenu.tsx:25-41`;
  `crates/silo-api/src/api.rs:351-362,494`.
  - **Mechanism:** earlier gates closed by deferring lows to Phase 8, and PROGRESS.md (the single source of truth,
    rule 9) still lists them as Phase 8 work. Phase 8 only addressed phase-4 L9 / phase-5 L7 (back button,
    `aria-pressed`, loading `role="status"`, Remove confirmation). The rest are unchanged in the code:
    - phase-6 L6 `keyFromVk` still maps VK codes with a US layout. For a de UI user this is a real bug: on a German
      keyboard `#` is `VK_OEM_2` (0xBF) and maps to `/` (volume down, `player.ts:247,316`), Shift+3 (`§`) becomes `#`
      (audio cycle, L308), and `?` cannot be produced — whenever the native video window has focus;
    - phase-5 L11: `ContextMenu` still re-runs its effect on every parent render (inline `onClose` from
      `PosterCard.tsx:92`) and moves focus back to the first item. This belongs to "accessibility basics";
    - phase-5 L12: the artwork scheme still accepts any https host incl. loopback/private addresses (security review
      in Phase 10 will ask);
    - phase-5 L1/L2/L4/L6/L8, phase-6 L4/L5/L10, and next episode across a season boundary are untouched.
  - **Failure scenario:** Gate 8 is marked PASSED and Phase 8 DONE while PROGRESS.md still says these items are Phase 8
    work, so they drop out of every remaining phase. A German user (de is a required UI language) presses `#` during
    playback to change the audio track and the volume goes down instead.
  - **Fix:** fix at least phase-6 L6 (send the translated character with `ToUnicode`/`WM_CHAR` from the video window)
    and phase-5 L11 (stable `onClose` via `useCallback`, or focus only on mount). Re-target the rest in PROGRESS.md
    explicitly (Phase 10 security review for L12, or "accepted for 0.1" with a reason).

### Low

- **L1 The Remove confirmation drops keyboard focus.** `Home.tsx:92-121`. The ternary swaps the focused "Remove"
  button for a fragment with two new buttons (and back on Cancel). React unmounts the focused element, focus falls to
  `<body>`, and the next Tab starts at the top of the page. Nothing announces the confirm state. Fix: keep the
  element (toggle its label), or focus the confirm/cancel button and return focus to "Remove" on Cancel.
- **L2 Two version sources.** `about.rs:38` (About) and `about.rs:150` (export header) use `env!("CARGO_PKG_VERSION")`
  (workspace `Cargo.toml` 0.1.0). The start-screen footer and user agent use `app.package_info().version`
  (tauri.conf → `package.json`), chosen deliberately in an earlier review (`lib.rs:115`, "review M6"). They agree today;
  a release that bumps only `package.json` shows two versions. Fix: pass the `AppInfo` version into `about_info` and
  the export.
- **L3 No visible way back from the standalone `/about` and `/settings` routes.** `App.tsx:68-84`. The routes reached
  from the start screen (`Home.tsx` links) render without the Shell and without a back button. Only Alt+Left or the
  mouse back button works. Fix: a back link to `/`, like the one Profiles got.
- **L4 Relay route tokens are not redacted.** `playback/relay.rs:118` builds `http://127.0.0.1:<port>/r/<token>/<name>`.
  mpv warn/error lines are forwarded to the log verbatim (`host.rs:637-646`), and a failed open can contain that URL.
  The token is a 128-bit loopback-only capability, the Host header is checked, and it is dead after the attempt, so the
  impact is negligible. Fix (optional): mask `/r/<token>/` in `redact()`.
- **L5 `docs/perf.md` precision.**
  - L17 says the cold start is measured "from process start". The host's `cold_start_ms` starts at `run()`
    (`lib.rs:176`), after process creation and static DLL loads. The wall-clock column does start at process launch.
    Say which is which.
  - "About 1.2 s … between mpv choosing the decoder and the first playback-restart" (L55) has no evidence file.
    The `[vd] Using hardware decoding` lines were not saved.
  - Cold start and idle memory come from the `9bdbb5c` tree (`perf.json` `measuredAt` 15:21). They were not
    re-measured after `5317a45`/`6c7fff8`, or the uncommitted mpv.conf layering, which also affects TTFF.
  - Idle memory was taken on the start screen (no library or artwork loaded), which is a best case. Label it so,
    or add a ServerHome idle number.
  - "mpv … adds nothing at idle" (L51-52): the core is lazy, but `libmpv-2.dll` is loaded at startup by the
    delay-load probe (`build.rs:57`, `crates/player/src/probe.rs`).
  - TTFF ran with HDR mode off, so the HDR10 clip went through the tone-mapped SDR path. The HDR-on-desktop TTFF
    (primary target) is only a checklist item.
- **L6 `perf.json` has a UTF-8 BOM.** `scripts/measure-perf.ps1:114` uses `Out-File -Encoding utf8`, which writes a BOM
  on Windows PowerShell 5.1. Node's `JSON.parse` rejects the file (verified). Fix: write it with
  `[IO.File]::WriteAllText($Out, $json, (New-Object Text.UTF8Encoding $false))`.
- **L7 Live regions are inconsistent.** Loading text has `role="status"` on Home, Profiles and About, but not on
  ServerHome (`ServerHome.tsx:87`), Library (`Library.tsx:78`), Item (`Item.tsx:93,235,258,332`) or Settings
  (`Settings.tsx:191,317`). The offline banner element is mounted already filled (`OfflineBanner.tsx:22-31`), which
  some screen readers do not announce. A permanently mounted, empty `role="status"` container whose text changes is
  reliable.
- **L8 Export folder.** `about.rs:165-169` uses `%USERPROFILE%\Downloads`. If the user moved Downloads (folder
  Properties → Location), `create_dir_all` creates a stray new `Downloads` folder. The path is shown, so the file can
  still be found. Fix: `SHGetKnownFolderPath(FOLDERID_Downloads)`.
- **L9 Source link precision.** `about.rs:14` points at the repository root, which is private (a 404 for anyone but
  the owner). No build commit is shown, while ADR-0005 says each binary release links to the exact source commit.
  This is fine while distribution stays private. Before any third-party distribution, embed the commit (e.g.
  `GRANARY_GIT_SHA` at build time) and link to it.
- **L10 Onboarding when the server list fails.** `Home.tsx:27-30` sets `servers` to `[]` on a `servers_list` error. An
  unreadable server store therefore looks like a first run (onboarding steps plus an error alert), which invites
  re-adding servers that still exist. Fix: keep `servers` null and show the error with a retry.
