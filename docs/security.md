# Security review (Phase 10)

Scope: Granary 0.1.0. Reviewed on 2026-11-07 at commit 950ca33 and later.

The threat model has four sources of risk:

- **The Silo server and anything it returns.** This includes metadata, artwork references, stream plans and
  WebSocket events.
- **The network path to it.** That can be the LAN, the internet, or a proxy.
- **Other local processes and web pages.** This covers loopback services and DNS rebinding.
- **Granary's own WebView.** Any script running in it holds the main window's capability.

The goals are:

- Tokens never leave the Rust host, except to the server's own origin.
- The WebView cannot be turned into a general-purpose browser or a local file or network proxy.
- Logs never contain secrets.
- Display changes are always undone. This is a safety property; see ADR-0006.

Each section below lists what is in place, with file references and tests, and any residual risk that is accepted
for 0.1, with the reason.

## 1. Tauri capabilities and CSP

**Capability.**
- `apps/desktop/src-tauri/capabilities/main.json` grants the `main` window 42 `allow-<command>` permissions, one for
  each of Granary's own commands. These are generated by `build.rs` from `COMMANDS`.
- The only other grants are `core:event:allow-listen` and `core:event:allow-unlisten`.
- No core or plugin permission is granted: no shell, fs, http, dialog, opener or updater plugin.
- The two plugins in use need no grants: single-instance and window-state.
- `ipc-contract.test.ts` enforces all of this. It checks that the capability, `generate_handler!` and build.rs list
  exactly the same commands. It also checks that nothing else is granted, and that every command is used by the UI.

**CSP** (`tauri.conf.json`):
- `default-src 'self'` and `script-src 'self'`. There is no `unsafe-eval` and no inline script.
- `object-src 'none'`, `media-src 'none'`, `form-action 'none'`, `frame-ancestors 'none'`, `base-uri 'self'`.
- `img-src` allows only the app, `data:`/`blob:` and the host's `granary-img` scheme. No remote image origin is
  allowed.
- `connect-src` allows only the app and Tauri IPC. The WebView never talks to the server itself (ADR-0004).
- `style-src 'unsafe-inline'` is needed by Radix/Tailwind runtime styles. It is accepted because script injection,
  not style injection, is the risk here, and script is locked down.
- `freezePrototype: true`.

**Navigation.**
- `lib.rs` `navigation_allowed` keeps the top-level document on the app's own origin (`tauri://localhost` /
  `http(s)://tauri.localhost`).
- The dev server is allowed only in debug builds.
- Remote pages, the artwork scheme and the IPC origin can never become the document (phase-5 review M3). This is
  covered by the tests in `lib.rs`.

**Debug-only paths.**
- WebView devtools are not enabled in release builds: Tauri's `devtools` feature is not turned on.
- `GRANARY_MOCK_SERVER` is honoured only when `cfg!(debug_assertions)` is set.
- The remote-debugging port used by the measurement scripts comes from an environment variable that the developer
  sets for `tauri dev`. Nothing in the app opens it.

## 2. IPC command surface

**Commands.**
- There are 42 commands; see the list in build.rs.
- Arguments are typed serde structs and enums. Unknown enum values are rejected by deserialisation.
- `open_link` takes a `Link` enum (`Source | Releases | License | LogFolder`) and never a URL or path. The test
  `links_are_a_fixed_allow_list` covers it.
- `player_set` accepts only an allow-list of mpv properties. Arbitrary mpv commands such as `run`, `loadfile` or
  `script-message` cannot be reached from the UI.
- Settings are validated and clamped on the host before they reach mpv or the display layer.

**Errors.**
- They cross the IPC boundary as `{ code, message }`.
- Every message is built through `CommandError::from` or `CommandError::plain`, and both pass it through the same
  redaction as log lines. A redirect location or problem detail that quotes a token therefore reaches the UI masked.
  The test is `command_errors_are_redacted`.

**Residual risk:** none known. A compromised WebView could call any of the 42 commands, which is the intended UI
surface. With them it can sign in, browse and play, but it cannot read tokens, files or arbitrary URLs.

## 3. Remote-content exposure

**Server metadata.**
- React renders it as text. There is no `dangerouslySetInnerHTML`, `innerHTML` or `eval` in `apps/desktop/src`
  (checked with grep).
- The test `no-video.test.ts` keeps all media out of the WebView.

**Artwork** (`catalog.rs`, `silo-api` `resolve_artwork_url` / `fetch_image`):
- The host fetches it without credentials. Same-origin URLs and `https` URLs are allowed.
- Foreign hosts that are `localhost` names or loopback, private, link-local, CGNAT or unspecified IP literals are
  refused (phase-5 L12). The test is `foreign_artwork_hosts_must_be_public`.
- URLs with embedded credentials are refused, and so are non-http(s) schemes.
- Redirects are never followed.
- The body is capped at 16 MiB.
- Only raster types are served (JPEG, PNG, WebP, AVIF, GIF). SVG is never served.
- Every scheme response carries `Content-Security-Policy: default-src 'none'; sandbox` and `nosniff`.
- **Residual risk (accepted):** a public DNS name that resolves to a private address still passes the check. The
  request is a blind, credential-less GET whose answer is only shown if it is an image, which is the same exposure as
  an `<img>` in any browser. Pinning resolution would need a custom resolver for one low-impact case.

**Media** (`playback/relay.rs`, ADR-0008):
- mpv only ever opens loopback relay URLs, `http://127.0.0.1:<ephemeral>/r/<128-bit token>/<name>`.
- The relay binds 127.0.0.1 only.
- It requires `Host` to be exactly that address, which defeats DNS rebinding.
- It answers only GET and HEAD for registered tokens. Paths below a route cannot leave the route's directory.
- It forwards only range and conditional request headers, and it forwards only a safe set of response headers.
- Routes are dropped when playback stops.
- Other local processes could reach the port, but they would need the unguessable token. A token is never logged
  (phase-8 L4) and lives only for one playback.

**mpv hardening** (`crates/player/src/options.rs` `forced`):
- Settings are applied in this order: `config=no` (no mpv.conf or input.conf of its own), the bundled
  `mpv.conf`, then the optional user `%APPDATA%\Granary\mpv.conf`, then `forced`.
- Every `forced` option is applied last, so the user file cannot override it:
  - `input-default-bindings=no` and `input-vo-keyboard=no`: keys go to the host instead.
  - `osc=no`, `terminal=no`.
  - `ytdl=no`: mpv never starts `yt-dlp` from `PATH` when a URL fails to load.
  - `load-scripts=no`: no scripts are auto-loaded.
- The user mpv.conf belongs to the person running Granary on their own PC. It is treated as trusted, the same way
  mpv treats its own config.

**WebSocket events** (`silo-api` `events.rs`, `playback/events.rs`):
- Frames are parsed into typed variants.
- Unknown frame types are dropped.
- Server events go to the UI as JSON data, which the UI uses only to refresh views. Their payloads are never logged.
- The ticket travels only in the `silo.ticket.*` subprotocol, which is redacted from logs.

## 4. Token handling and log redaction

**Storage** (ADR-0004):
- The refresh token is kept in Windows Credential Manager, under target `<server>/<user>.Granary`.
- The access token and `X-Profile-Token` are kept in memory only. The PIN is asked again after a restart.
- The UI never receives a token. Commands return views without secrets.

**Scoping.**
- The bearer and profile headers are attached only to requests to the configured server origin.
- Redirects are never followed by the API client.
- The relay sends credentials upstream only for same-origin stream URLs. Foreign stream URLs rely on their `st`
  signature.

**TLS.**
- rustls with the platform verifier (the Windows certificate store).
- Plain `http://` is allowed only after an explicit warning in the add-server flow (`servers.warnInsecure`).

**Redaction** (`apps/desktop/src-tauri/src/redact.rs`):
- Every log line passes through `RedactingWriter`.
- It masks the values of secret keys in the `key=value`, JSON, Debug, escaped-Debug and percent-encoded forms.
  Secret keys include `token`, `password`, `pin`, `st`, `sig`, `ticket`, `authorization`, `api_key`, `cookie` and
  `secret`.
- It also masks bearer and basic credentials, bare JWTs, `silo.ticket.*` WebSocket subprotocols and relay route
  tokens.
- ANSI codes are stripped before matching, and the writer never panics on arbitrary UTF-8.
- The log viewer and log export apply redaction again.
- Tests: 12 in `redact.rs` and 2 in `about.rs`.

**Repository.**
- `scripts/secret-scan.ps1` runs before every push and in `verify.ps1`.
- `.env.local` is gitignored and never read by the app.

## 5. Dependency audits

| Tool | Command | Result |
| --- | --- | --- |
| cargo-audit 0.22.2 | `cargo audit` (554 crates) | exit 0: **no vulnerabilities**; 5 warnings, listed below (`docs/evidence/phase-10/cargo-audit.txt`) |
| pnpm 12.18.0 | `pnpm audit --prod` | exit 0: no known vulnerabilities |
| pnpm 12.18.0 | `pnpm audit` (including dev) | exit 0 after the `minimatch` override below; before it, 1 moderate |

cargo-audit warnings. All five come from Tauri's Linux backend (GTK/glib, zbus) and are not compiled into the
Windows build. The `cargo tree --target x86_64-pc-windows-msvc -i <crate>` output is in the evidence file.

- `glib` 0.18.5 RUSTSEC-2024-0429 (unsound `VariantStrIter`).
- `proc-macro-error` RUSTSEC-2024-0370 (unmaintained).
- `zbus_names`, `zvariant` and `zvariant_derive` RUSTSEC-2026-0370/0371/0372 (unmaintained).

These are accepted until Tauri updates its Linux dependencies.

Dev dependency: `minimatch` 10.2.6, GHSA-g3hv-75wg-m249 (ReDoS through glob patterns).
- It is reached only through the eslint toolchain, and its input is the repository's own glob patterns.
- It is fixed anyway with a pnpm override to `^11.0.1` in `pnpm-workspace.yaml`. eslint and the full verify run pass
  with it.

## 6. Accepted residual risks

| Risk | Why it is accepted for 0.1 |
| --- | --- |
| Unsigned installer (SmartScreen warning) | Private test release; signing is planned in `docs/signing.md` |
| Plain `http://` servers can be added | Common on home LANs; the user is warned explicitly before adding one |
| DNS names that resolve to private addresses pass the artwork host check | Blind, credential-less, image-only GET (section 3) |
| `style-src 'unsafe-inline'` | Needed by the UI library; script stays `'self'` only |
| Linux-only crates with RustSec warnings | Not part of the Windows build (section 5) |
